# 自建线路自动回退、手动切换与国内直连

本教程使用自己的 VPS：HY2 主线路、WebSocket CDN 备用和 IPv4 VLESS 备用；IPv6 验证可用后作为手动备用。无需另购 VPN 或接入外部订阅。先在「订阅」页选择自己的配置，再在「代理」页保持「规则」模式。

## 选择脚本与界面

| 配置方式 | 使用文件 | 自动入口与手动操作 |
| --- | --- | --- |
| 基础界面 | [shared-profile.js](../scripts/shared-profile.js) | 「上网线路」选「自动切换（推荐）」；手动时在同一组直接选节点 |
| 可选简化界面 | 在基础脚本末尾追加 [simplify-panel.js](../scripts/simplify-panel.js) | 「上网方式」选「自动上网（推荐）」；手动时按下方两步操作 |

脚本只绑定本教程的自建配置，不安装到全局扩展脚本，也不覆盖其他已有配置。当前公开脚本遇到非空 `proxy-providers` 会停止并提示使用独立配置，避免将外部订阅混入自建路线。已有私人扩展需求应保留在自己的独立配置中。

## 自动回退如何工作

`fallback` 按 HY2 → CDN → IPv4 的优先级选择可用线路。主线路仍通过健康检测但视频或下载变慢时，不保证切换，也不会始终挑选所有节点中延迟最低的一个。此时先查看实际业务、选中线路和检测结果，必要时手动切换已验证的备用线路。

健康检测每 15 秒进行一次，超时为 5 秒；15 秒是检测间隔，不是恢复时限。回退作用于新连接，已失败请求可能需要应用重试。同一 VPS 的多条线路共享服务器和出口等故障点，整台 VPS 不可用时，这些备用线路也可能全部失效。

2026-09-28 对照本仓库脚本及 Mihomo 官方 [fallback 文档](https://wiki.metacubex.one/config/proxy-groups/fallback/) 核对：公开版保留优先级回退。实际部署仍须完成 [故障与恢复验收](verification.md)。

## 简化界面的手动选择

以下步骤只适用于追加 `simplify-panel.js` 后的界面：

1. 在下方「全部节点列表」选择已验证的自建节点。
2. 在上方「上网方式」点击「切换到手动节点」。
3. 确认上方当前方式已变成手动，下方当前节点是目标节点，并查看新连接是否经过它。
4. 恢复日常使用时，在上方点回「自动上网（推荐）」。

只选下方节点不会自动改变上方模式。手选节点故障时不会自动换线，要改选可用节点或返回自动。客户端可能记住上次手动/DIRECT 选择，重新激活不保证回到默认；以实际选中项与连接记录为准。

## 国内直连与 DNS

规则命中的国内域名与 IP 走 DIRECT，其余进入「上网线路」或简化后的「上网方式」。自动和手动模式都适用；国内识别基于规则与访问目标。Cloudflare 等显式直连例外见 [部署指南](deployment.md)。

如果客户端开启全局 DNS 覆写，脚本内 DNS 可能被覆盖。请按 [domestic-dns.example.yaml](../templates/domestic-dns.example.yaml) 合并国内直连 DNS，并查看最终运行配置确认生效；保留现有其他 DNS 设置。海外代理线路不可用时应单独验证国内访问，Clash 内核/TUN 本身故障或本地断网仍会影响国内访问。

## 验证范围

当前离线回归检查自建线路排序、IPv6 手选、脚本重复执行、凭据保留、国内规则和两种面板。它们不能证明新 VPS 的实际握手、故障回退或长期稳定性；真实部署按 [验收清单](verification.md) 留结果。

客户端曾出现旧 Timeout 标签与实际访问不一致的情况，显示刷新根因尚未确认。重新检测并查看真实请求和连接记录，不能将所有 Timeout 都当作缓存，也不能单凭标签判断节点可用性。

其他电脑按 [家庭设备配置步骤](family-client-setup.md) 安装并独立验收，不能用第一台电脑成功代替。
