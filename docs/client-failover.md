# 海外节点失效时，国内网站仍能直连

适用于本仓库的基础节点模板和扩展脚本。国内网站先匹配显式域名与 `GEOSITE,cn,DIRECT`，再用 GeoIP 兜底；海外流量进入自动组。仅靠国内 IP 判断会漏掉使用其他地区 CDN 的国内网站。

## 先保证国内分流与 DNS 独立

1. 更新 `scripts/shared-profile.js` 并重新激活配置。脚本依赖可用的本地 `geosite.dat` 和 GeoIP 数据；数据缺失应先修复，不删除规则绕过校验。
2. 脚本为直连流量及代理服务器域名配置直连 DNS。Clash Verge 若开启了全局 DNS 覆写，把 [DNS 示例](../templates/domestic-dns.example.yaml) 的字段合并到客户端实际 DNS 设置；保留现有 Fake-IP、监听和 TUN 字段，不整文件替换。
3. 核对生成的运行配置：`direct-nameserver` 使用带 `#DIRECT` 的国内 DoH，bootstrap 为国内 DNS，国内域名在最终代理规则之前匹配 DIRECT。
4. 保持规则模式。全局模式不等于国内直连；切换到其他订阅卡片会改用该订阅的分流规则。

脚本覆盖视频、政府、搜索、社交等国内域名及已识别资源，包括 B站、腾讯视频、爱奇艺、优酷、咪咕、政府 `gov.cn` 子域、百度、搜狗、360、微博、知乎、小红书、豆瓣等。它没有保证任意外链或所有第三方播放资源都属于直连范围。

## 按需加入其他订阅的日本节点

1. 先备份当前脚本与覆写配置。仅使用自己已拥有且允许使用的订阅，不为此额外购买。
2. 在自己的私有覆写中合并 [日本 provider 示例](../templates/japan-providers.example.yaml)，替换地址；只有一份订阅时删除另一个示例项。占位地址不是可用订阅，填写后的 URL 等同凭据，不能公开。
3. provider 名称保留 `japan-primary` / `japan-secondary`。脚本识别这些名称后，在 HY2 → CDN → IPv4 之后追加“日本低延迟（跨订阅）”。节点保存在 provider 中，不混入四节点模板的 `proxies`，避免角色冲突。
4. 每个 provider 自己启用健康检查：15 秒间隔、5 秒超时、HTTPS 204、`lazy: false`。组的检测不能替代 provider 的健康检查。名称过滤按日本标识筛选，再用 A/B 前缀区分同名节点。
5. 重新激活，选择“上网线路 → 自动切换（推荐）”。确认日本组出现真实节点及成功检测记录；空组使用 REJECT，不退回 DIRECT。

没有这些 provider 时，不生成日本备用组。日本组按可用性和延迟选择，50ms 容差减少抖动；这不是带宽测速，也不保证出口物理位置。主线路恢复后优先回到原线路。界面订阅卡片保持原选择，不会跟随节点切换。

provider 示例每 12 小时直连更新，后续使用本地缓存。首次订阅下载失败或没有日本节点时不能把备用视为可用；需要代理才能下载的订阅应另行评估启动依赖，避免通过尚未加载的自身节点下载自身。

## 故障验收与恢复

先在独立 Mihomo 进程和本机测试端口验证，关闭测试进程的 TUN，避免接管现有连接：

- 将测试进程的主节点改为不可达，保留有效备用，确认新 HTTPS 请求经备用成功；恢复主节点后检查回切。
- 禁用测试进程全部海外出口，国内四类入口应仍命中 DIRECT；海外地址应失败，不要使用 MATCH,DIRECT 掩盖故障。
- 覆盖 Fake-IP 的 DNS 查询与连接映射，再在实际客户端分别检查系统代理与 TUN。
- 用连接日志核对规则与最终出口，区分 HTTP 200、跳转、403、登录和完整播放。UI Timeout 可能是旧测速，不能替代内核状态与真实请求。

检测间隔不是恢复时限，已有连接不会迁移或自动重放。Clash 内核停止、TUN 故障或宽带中断仍可能影响国内访问。回滚前保留本次修改，恢复此前脚本与 DNS/覆写文件，重新激活并复验；不要覆盖后续用户修改。

## 已有证据与未验证项

2026-09-20，维护者在现有 Mac 客户端进行的配置验证包括：主线路故障后转入另一订阅、恢复回切；海外出口固定 REJECT 时，20 个国内站点全部命中 DIRECT（15 个 200、4 个 302、1 个 403）；百度、钉钉、政府网的 Fake-IP 连接路径通过。以上只证明所测路径，不代表新服务器完整部署或每个站点的登录/播放验收。

现有客户端曾出现 UI 延迟与流量显示滞后，后续复验恢复显示流量和节点延迟；没有确认根因或长期不复发。公开模板还需使用者替换自己的参数后验证，不能直接使用维护者的样本结果作为验收。

字段依据（2026-09-20 核对）：[Fallback](https://wiki.metacubex.one/config/proxy-groups/fallback/)、[URLTest](https://wiki.metacubex.one/config/proxy-groups/url-test/)、[provider](https://wiki.metacubex.one/config/proxy-providers/)、[DNS](https://wiki.metacubex.one/config/dns/)。

同日公开通用脚本也使用私有测试输入在独立进程中验证：主节点不可达时自动选择日本备用，海外 HTTPS 返回 204、政府网返回 200。私有输入未进入公开仓库；仍需在使用者自己的环境复验。


## 可选：把日常面板简化为用途选项

如果后台组和节点列表让你难以判断应该选哪个，可把 [simplify-panel.js](../scripts/simplify-panel.js) 的内容追加到 [shared-profile.js](../scripts/shared-profile.js) 后面，两段作为同一份扩展脚本使用；不要把可选脚本单独安装。先备份当前脚本，保存后重新激活订阅，打开「代理」页并展开「上网方式」。

| 选项 | 何时使用 |
| --- | --- |
| 自动上网（推荐） | 日常使用；自有线路优先，失效后自动转日本备用 |
| 日本上网（自动测速） | 希望代理流量直接选择日本出口；只有配置 provider 后才显示 |
| 直连上网（不经代理） | 临时直接连接，不提供代理出口 |

保持顶部「规则」模式。国内规则继续直连，蓝色卡片表示当前方式，第二行显示底层线路。后台组隐藏后仍持续检测。默认推荐在首位；如果手动改变过该组排序，可恢复默认排序。此布局隐藏单节点手选入口，需要完整排障面板时移除追加段并重新激活订阅。

可选布局通过离线回归；维护者本机同等布局已实际点击日本模式，海外 HTTPS 检测返回 204、国内政府入口返回 200，并切回推荐项。此证据不是新 VPS 部署验收。客户端加载时曾短暂保留旧 Error，实际选择后恢复；刷新显示问题的长期修复未验证。用户视觉体验仍需自行确认。

## 只在当前订阅内优先日本节点

如果当前订阅本身包含日本节点，可使用 [subscription-japan-url-test.js](../scripts/subscription-japan-url-test.js)。它只匹配当前配置中名称带日本、Japan、JP 或日本国旗的节点，按 15 秒间隔测试可用性和延迟，并将日本测速组设为默认入口；没有日本节点时保持原配置。不要把个人订阅链接、缓存或私有配置复制到其他设备。
