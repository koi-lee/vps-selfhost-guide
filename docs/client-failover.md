# 代理面板简化与使用说明

日常只需打开 Clash Verge 的「代理」页，保持顶部「规则」，在「上网方式」中选择「自动上网（推荐）」。订阅页继续启用 lizean，无需在订阅卡片之间来回切换。

## 三个选项怎么用

| 选项 | 适用场景 | 实际行为 |
| --- | --- | --- |
| 自动上网（推荐） | 日常使用 | 自有 HY2 → CDN → IPv4 TLS，全部不可用再用其他订阅的日本节点；恢复后回到优先可用线路 |
| 日本上网（自动测速） | 明确需要日本出口 | 在已有新、旧订阅的日本候选中自动测速选择；50ms 容差减少抖动，不承诺每一刻绝对最低延迟 |
| 直连上网（不经代理） | 临时不使用代理出口 | 本来进入此代理组的连接也直接访问；不会因此获得访问海外网站的能力 |

国内网站按原有国内直连规则处理，在推荐与日本两种方式下也继续直连。蓝色卡片代表选中的上网方式，卡片第二行是它当前使用的底层线路；延迟数字是测速结果，不是必须手动挑选节点的提示。切换主要影响新连接，已有连接可能需要重新打开。

## 原来的问题与修改

原界面把主入口、自动故障切换、日本测速池并列显示，展开后有 20 个节点。后台日本组中的蓝色节点容易被误认为整个客户端正在使用的出口。

v16 保留一个可见的「上网方式」选择组，按推荐、日本、直连排列；故障切换、测速池和直连包装组设为隐藏。后台检测保持 lazy=false，健康检测参数、跨订阅候选和国内 DNS 不变。本次不修改 Clash Verge 二进制；协议标签和工具栏图标仍是客户端原生界面。手动选择单条自有线路不再出现在日常入口；如需排障可恢复 v15 后查看全部组。

核对了 Clash Verge Rev v2.5.2 的 [use-head-state.ts](https://github.com/clash-verge-rev/clash-verge-rev/blob/v2.5.2/src/components/proxy/use-head-state.ts) 与 [use-filter-sort.ts](https://github.com/clash-verge-rev/clash-verge-rev/blob/v2.5.2/src/components/proxy/use-filter-sort.ts)：排序偏好按订阅和组名存储，默认按配置顺序显示。因此新入口使用语义更明确的「上网方式」，初始展示顺序不受旧「上网线路」的测速排序影响。用户之后仍可自行改排序。

## 旧订阅的日本自动测速

旧订阅现在使用单独脚本 `旧订阅-日本自动测速-20260920.js`。切换订阅到「旧」并重新激活后，代理页的「上网方式」会默认选择「日本上网（自动测速）」；它只收集旧订阅中名称带日本/Japan/JP 的节点，每 15 秒检测一次，以可用性和延迟选择节点。国内规则仍排在最终代理规则之前，命中的国内网站继续 DIRECT。

这条逻辑只改变「旧」订阅；lizean 仍保持自有线路优先，新订阅仍按原有配置处理。旧订阅没有日本节点时不会伪造测速组，会保留原配置。给另一台电脑复用时，不要复制本机订阅链接或配置文件：先导入同一个「旧」订阅，在该订阅的扩展脚本位置粘贴这份脚本，重新激活后检查「上网方式 → 日本上网（自动测速）」；订阅凭据由她本人输入。

## 手动选择其他国家

旧订阅的代理页还会显示「手动选择节点（全部国家）」。平时保持「日本上网（自动测速）」；需要美国、香港、新加坡等出口时，点击「手动选择节点（全部国家）」展开节点，再点击目标国家的节点。主入口会显示当前手动选择的节点。手动选择不会删除日本自动测速组；下次需要自动选择时，再点回「日本上网（自动测速）」。
