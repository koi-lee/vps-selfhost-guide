# 验收与恢复

默认验收目标是 HY2、CDN、IPv4 VLESS 三条自建线路与自动回退。先验证 HY2，再继续备用和完整客户端；阶段成功不等于完整部署结束。

## 离线检查

在仓库根目录运行：

```sh
node --test tests/*.test.js
python3 tests/check_docs.py
python3 tests/check_copy.py
python3 tests/check_i18n.py
```

这些检查覆盖脚本行为、文档链接及翻译源一致性，不能替代服务器真实部署。模板带占位符，不能直接连接。

## 每次部署必须完成

- 记录系统、Hysteria/Xray、Clash Verge Rev/Mihomo 版本、官方安装来源及配置检查结果。
- 记录端口、服务用户、证书域名和权限；服务监听符合计划，SSH 与救援入口可用。
- 在本机客户端明确手动选中每条已部署线路，对至少两个 HTTPS 目标各测 5 次，记录成功、失败和超时。核对连接记录中的实际节点，不能用 VPS 自己访问网页、端口开放或控制 API 200 代替。
- 返回自动模式，访问国内与海外站点，核对 DIRECT 与代理路径；完成小文件上传、下载。
- 重启客户端后配置与模式仍正确；在已授权窗口重启 VPS，验证服务自启动和真实请求。
- 检查证书续期任务、安装路径、权限及部署钩子；实际续期后还需检查运行证书和请求结果。仅检查了任务时，记录“续期任务已检查，实际续期未验证”。不要反复强制生产签发。

## 三线路故障回退

先取得故障演练授权并保留 SSH 与上一份可用配置。在隔离客户端或测试环境中优先模拟故障，避免中断其他使用者；记录具体模拟方法和恢复动作。

1. 核对三条线路各自成功，自动组顺序为 HY2 → CDN → IPv4，且当前处于自动模式。
2. 临时使测试环境中的 HY2 不可用，保留 CDN/IPv4 可达。观察检测结果，发起新请求并确认使用 CDN。
3. 在 HY2 仍不可用时，再使测试环境中的 CDN 不可用，发起新请求并确认使用 IPv4。
4. 恢复本次改动，等待健康检测后核对自动组实际选择与新请求，确认主线路重新可用。
5. 按已授权演练范围测试所有代理线路不可用时的国内 DIRECT，并确认恢复后海外访问正常。国内首页可访问不等于完整登录、上传或视频都通过。

记录实际切换时间，不将 15 秒检测间隔当作恢复承诺。只见组名、延迟数值或旧 Timeout 标签不算通过；真实请求和连接路径才是依据。默认线路缺少或上述切换未测时，报告“多线路部署/回退未完整验收”。

## 启用后才需要验收

| 选配能力 | 通过要求 |
| --- | --- |
| IPv6 手动备用 | 本地与 VPS 的 IPv6 均可用，手选该节点后真实请求成功；未启用时删除节点及引用 |
| 多用户 | 第二个独立身份能连接；撤销后不能新建连接，同时核对 HY2 和各 VLESS 入站 |
| 远程订阅 | 私密 HTTPS 获取与更新可用，token 能撤销；手动 YAML 分发不算自动订阅 |
| 管理面板 | 核对版本支持范围，回环监听、SSH 隧道可用，未向公网暴露管理入口 |
| TUN / 第二台电脑 | 按该设备实际环境验证，不复用第一台电脑的通过结论 |

未启用的选配能力记为“不适用”；已纳入目标但失败或未测的能力记为“未完成”。

## 恢复

改动前分别备份服务配置、适用的面板数据、unit、防火墙、客户端配置和扩展脚本，确认备份可读且恢复位置明确。配置检查失败不重载；连接失败时恢复上一个可用阶段，先保证 SSH 与已通过线路。

不要在故障时清空所有连接、重装系统或直接覆盖数据库。按 DNS → TCP/UDP → TLS → 认证 → 路由逐层排查。未经授权不通过修改正在使用的其他配置制造故障。
